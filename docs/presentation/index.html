How UEFI Optical ISO (El Torito) Works

On an ISO 9660 optical disc, legacy BIOS looked for sector 0 MBR boot code. UEFI systems do not execute sector code; instead, Sector 17 contains an El Torito Boot Record pointing to a Boot Catalog. The catalog has a record with Platform ID 0xEF (UEFI Entry) pointing directly to the embedded FAT32 image. When VirtualBox or a physical PC boots the ISO, the UEFI Boot Manager mounts the embedded FAT32 partition and executes \EFI\BOOT\BOOTX64.EFI in 64-bit long mode.

Interactive Viva Defense Simulator

Q1: Why is this not simply a Linux distro? +
Aeon does not contain the Linux kernel. It is a 462 KiB bare-metal microkernel written in 100% pure Rust. It implements a Linux ABI translation layer over MSR_LSTAR fast syscalls, allowing it to execute Linux binaries while running on our own custom scheduler, memory manager, and page tables.
Q2: How does the network stack handle packet loss? +
The TCP engine implements an RFC 793 retransmission timer with sequence number acknowledgment. If an ACK is not received within the timeout window, the segment is retransmitted. ICMP ping tracks packet loss percentages by comparing transmitted sequence IDs against received echo reply tokens.
Q3: Why use UEFI instead of legacy BIOS? +
Legacy BIOS executes in 16-bit real mode with severe 1 MiB memory limitations and requires complex multi-stage bootloaders (boot sector -> stage 2). UEFI hands off execution directly in 64-bit long mode with a pre-configured linear GOP framebuffer, hardware TPM 2.0 protocol access, and modern GPT partition support.
Q4: How do you prove preemption works? +
The kernel includes two test workers (spawn). Worker tasks that loop infinitely without voluntary yields are preempted every 10 ms by the 100 Hz Local APIC timer interrupt. The scheduler flight recorder trace (trace) logs every preemption with reason code Timer.
