> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, single session). Steps use checkbox syntax for tracking.

**Goal:** Read real files from a disk: find devices on the PCI bus, drive a virtio block device, and read FAT16/FAT32 volumes, so later steps can load programs from files.

**Architecture:** Pure logic (PCI header decoding, virtqueue ring arithmetic, FAT parsing) lives in host-tested modules; hardware access (config-space ports, MMIO, DMA memory from the frame allocator) is thin and UEFI-only. The block layer is a small trait so a later NVMe/AHCI driver plugs in. Every layer has a QEMU boot test.

**Tech Stack:** Rust `no_std`, polling virtio 1.0 over PCI (no interrupts yet), QEMU `virtio-blk-pci` with a raw disk image built by `tests/mkdisk.py`.

**Spec:** the user's "do all" for the storage room (2026-11-01) and `docs/design/aeon-system-design.md` section 7, item 3.

## Global Constraints

- Zero dependencies; image stays signed and under 200 KB (now 191 KB), so every new module must be small; if it does not fit, raise the budget in a ledgered decision, never silently.
- Read-only filesystem for now: no writes to a disk that is not Aeon's own.
- All device and disk data is untrusted: every length, cluster number and offset is bounds-checked, loops are bounded, nothing from the disk is trusted as a pointer.
- `clippy::undocumented_unsafe_blocks` stays denied; stage files by path; do not push.

## Review Focus

- A FAT image with a cluster chain loop, out-of-range cluster numbers, zero-length directory entries or sizes larger than the chain: must stop with an error, never hang or read outside the image.
- A disk smaller than one sector, or a device that never completes a request: the driver times out and reports an error.
- File names with long-name entries, lowercase, spaces, and 8.3 collisions: listing and lookup are case-insensitive and tolerate junk.
- No disk attached: every disk command says so and nothing else changes.

### Task 1: PCI scan

**Files:** Create `src/pci.rs` (pure decoding + UEFI-only port access), `tests/boot_test.py` `t_pci`; Modify `src/lib.rs`, `src/main.rs` (scan after memory init), `src/shell.rs` (`pci` command).

**Interfaces:** Produces `pci::Header { vendor, device, class, subclass, prog_if, header_type }`, `pci::parse_header(w: &[u32; 4]) -> Option<Header>`, `pci::class_name(class: u8, subclass: u8) -> &'static str`, `pci::Device { bus, dev, func, header }`, `pci::scan()`, `pci::devices() -> &'static [Device]`, `pci::config_read(bus, dev, func, off) -> u32`.

- [x] Unit tests first: `parse_header` rejects vendor 0xFFFF, decodes class/subclass/prog_if, header type masks the multifunction bit; `class_name` known and unknown values. Run (FAIL), implement, run (PASS).
- [x] `t_pci`: boot, `pci` lists `8086:29c0` and `Host bridge`; with a virtio disk attached it lists `1af4:1001` or `1af4:1042`.
- [x] Commit `feat(pci): bus scan and pci command`.

### Task 2: virtio-blk driver

**Files:** Create `src/virtio.rs` (ring math, pure) and `src/vblk.rs` (UEFI-only driver); Modify shell (`disks`), `tests/boot_test.py` (`Vm` takes `disk=`), `tests/mkdisk.py`.

**Interfaces:** Consumes Task 1. Produces `block::BlockDev` trait `{ fn sectors(&self) -> u64; fn read(&mut self, lba: u64, buf: &mut [u8]) -> Result<(), BlockError> }` (512-byte sectors, `buf.len()` a multiple of 512), `vblk::probe() -> Option<VirtioBlk>`, `virtio::avail_index_next(idx: u16) -> u16` style ring helpers.

- [x] Unit tests for ring helpers (wraparound, descriptor chain layout sizes). Boot test: `disks` prints the capacity of a 4 MiB image; reading sector 0 returns the first bytes written by `mkdisk.py`; with no disk it says `no disk`.
- [x] Implement polling requests with a 2 s timeout. Commit `feat(storage): virtio-blk driver`.

### Task 3: FAT reader

**Files:** Create `src/fat.rs` (pure, over a `read_sector` closure), `tests/mkdisk.py` writes FAT16 and FAT32 images; Modify shell (`dls`, `dcat`).

**Interfaces:** Produces `fat::Volume::open(read: impl FnMut(u64, &mut [u8]) -> bool) -> Result<Volume, FatError>`, `list_root`/`find`/`read_file` with a hard cap on chain length, `FatError { BadBpb, BadChain, TooBig, NotFound }`.

- [x] Unit tests with hostile images: loop in the chain, cluster beyond the table, directory entry pointing at cluster 0 with a size, truncated image, huge declared size. Plus happy paths from a fixture image built in the test.
- [x] Boot test: `dls` lists `HELLO.TXT`, `dcat hello.txt` prints its text, `dcat nosuch` says not found.
- [x] Commit `feat(storage): FAT16/FAT32 read-only reader`.
