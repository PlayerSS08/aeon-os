# AHCI (SATA) disk, read only: implementation plan

> **For agentic workers:** execute task by task; steps use checkboxes. Pure modules first (host tests), hardware last.

**Goal:** Aeon reads a real PC's SATA disk (and QEMU's emulated AHCI disk), so `disks`, `dread`, `dls` and `dcat` work on more than virtio-blk.

**Architecture:** A pure module (`ahcifis.rs`) builds the FIS, command header and PRDT entries and decodes capability, port and IDENTIFY data. A hardware module (`ahci.rs`) brings up the controller and implements `BlockDev` with polled DMA reads. A small `disk.rs` picks the first available disk (virtio, then AHCI) and gives the shell one `&mut dyn BlockDev`. No third-party crates, no interrupts, no writes.

**Spec:** `reports/Hobby Rust OS build checklist.md`, gap 4; notes in `research_notes/Hobby Rust OS build checklist/drivers_storage_net.md` (the OSDev AHCI page says its own example code has bugs: design is copied, code is not).

## Global Constraints

- Both clippy gates clean with `-D warnings`; every `unsafe` block has a `SAFETY:` comment.
- Read only. No write command is ever built.
- Only 512-byte logical sectors and 48-bit LBA disks; anything else is reported and ignored.
- Never push. Commit with the Scrooge-777 identity.
- Real PC disks may hold the owner's data: the driver never sends a command other than IDENTIFY DEVICE and READ DMA EXT.

## Review Focus

- A request that reaches past the end of the disk must be refused before any command is built.
- A port that never clears BSY/DRQ or never completes the command: time out, no hang.
- A controller that reports 64-bit addressing unsupported while buffers are above 4 GiB: refuse or bounce, never DMA to a truncated address.
- ATAPI (CD) and port-multiplier signatures: not touched.
- Task file error after a read: report `Io`, leave the controller usable.

### Task 1: Command structures and IDENTIFY parsing (pure)

**Files:** Create `src/ahcifis.rs`; modify `src/lib.rs`.

- [ ] Tests first: the READ DMA EXT FIS bytes for a known LBA and count (including LBA above 32 bits and count 0 meaning 65536 refused); the IDENTIFY FIS; the command header (FIS length 5 dwords, PRDT length, table address); a PRD entry (byte count minus one, odd or oversize counts refused); capability decode (ports, command slots, 64-bit flag); port classification from SSTS and SIG (empty, SATA, ATAPI, other); IDENTIFY parsing (model string with byte-swapped words, 48-bit sector count, 28-bit fallback refused, non-512 logical sector size refused, ATAPI bit).
- [ ] Implement the builders and decoders as pure functions over byte arrays.

### Task 2: The controller driver (hardware)

**Files:** Create `src/ahci.rs`; modify `src/lib.rs`, `src/main.rs`.

- [ ] Find PCI class 01, subclass 06, interface 01; map ABAR (BAR 5); take over from the firmware (BOHC); set GHC.AE.
- [ ] Per implemented port with a SATA drive: stop the engine, allocate the command list, received FIS and a command table, point the port at them, start FIS receive and the engine.
- [ ] IDENTIFY DEVICE, keep the model and sector count; reject unsupported disks with a logged reason.
- [ ] `BlockDev::read` with one command per request of up to 128 sectors, polled, with a timeout.

### Task 3: One disk interface (hardware)

**Files:** Create `src/disk.rs`; modify `src/shell.rs`, `src/vblk.rs`, `src/fat.rs` only as far as `&mut dyn BlockDev` needs.

- [ ] `disk::with_disk(f: FnOnce(&mut dyn BlockDev) -> R) -> Option<R>` picks virtio first, then AHCI; `disk::describe()` lists both with model and size.
- [ ] `disks`, `dread`, `dls`, `dcat` use it.

### Task 4: QEMU test

**Files:** Modify `tests/boot_test.py` (group `ahci`).

- [ ] Boot with `-device ahci,id=ahci -drive if=none,id=d1,file=<demo FAT image>,format=raw -device ide-hd,drive=d1,bus=ahci.0`; `disks` lists the SATA disk; `dls` shows the files; `dcat hello.txt` prints the text; `dread` of a sector past the end is refused; the old virtio group still passes.

### Real-hardware limits (state in the final report)

Only QEMU's emulated AHCI is tested. Disks behind NVMe-only machines (many new laptops) are not covered; the owner's `pci` output decides whether NVMe is next. Intel RST "RAID" mode hides AHCI disks behind a vendor mode: switch the firmware to AHCI to test.
