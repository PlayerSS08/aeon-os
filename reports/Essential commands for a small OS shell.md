# Eight file commands fill Aeon's real shell gaps

Aeon's shell needs **eight more commands now: cp, mv, touch, head, tail, wc, grep and find**. They are the file handling and text-reading tools that every comparable small system has and Aeon lacks, and they work on file arguments alone, with no pipes, users, clock or network. A short "later" tier (hexdump, sleep, stat, cmp, a pager) and a long "left out" list follow, sorted by what each command would depend on. Putting "every Linux command" into a micro OS is neither possible nor useful: most commands rely on things Aeon deliberately does not have, and the commands people really type are a tiny set that Aeon already covers. The prompt should show the full current folder, with no `~` abbreviation. `write` should refuse to replace an existing file unless given a force flag, with the same rule applied to `cp` and `mv`. That last point is a design choice, not a sourced convention, and the notes say so below. Everything here comes from reading specifications and other small systems' command lists; Aeon's own source was not inspected.

## "Every Linux command" is impossible and pointless

**Source-backed.** The POSIX utilities index names roughly 160 utilities, and a large share are mail, print queues, SCCS version control, schedulers and compilers ([POSIX index](https://pubs.opengroup.org/onlinepubs/9699919799/idx/utilities.html)). BusyBox lists hundreds of applets and tells builders to pick the ones they want with `make menuconfig` because it was written "with size-optimization and limited resources in mind" ([BusyBox docs](https://busybox.net/downloads/BusyBox.html)). SerenityOS ships about 200 utilities ([third-party summary, low confidence](https://www.mintlify.com/serenityOS/serenity/architecture/userland)). Small teaching systems go the other way: the xv6 build installs **20 user programs**, and the shell-tool core is only cat, echo, grep, kill, ln, ls, mkdir, rm, sh and wc ([xv6-riscv Makefile](https://github.com/mit-pdos/xv6-riscv/blob/riscv/Makefile)). Real usage is concentrated too. In the one frequency dataset the research found (self-selected, 2019), the top entries are `ls` (1,044,749 uses), `clear` (354,638), `pwd` (335,139) and `cd ..` (225,533) ([Webminal](http://webminal.org/fulc/)). Aeon already has all of those.

**Inference.** The impossibility is structural, not about effort. POSIX commands assume permissions, users, processes you launch from files, a wall clock and a network, so a shell without them can implement a subset at most and cannot claim conformance. The pointlessness follows from the missing pipes and redirection: filters such as `tr`, `cut`, `uniq`, `tee` and `xargs` earn their place by chaining, and alone they have little to do. With no loadable programs, a long command list also cannot be extended by users, so every command is something you must write, test and document. Each one has to justify itself against that cost.

## Add now: eight commands, one line of behaviour each

**Source-backed basis.** The xv6 set lacks cp, mv and touch, but `cp` appears in the BusyBox, SerenityOS, Redox, Plan 9 and POSIX lists, `grep` and `tail` in all of those too, and `head`, `wc` and `touch` in BusyBox and POSIX ([Redox book](https://doc.redox-os.org/book/system-tools.html), [Plan 9 index](https://plan9.io/sys/man/1/INDEX.html), [SerenityOS utilities](https://github.com/SerenityOS/serenity/tree/master/Userland/Utilities)); Plan 9's index has no `mv` and no `head`. POSIX defaults: `head` and `tail` show 10 lines ([head](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/head.html), [tail](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/tail.html)); `wc` prints lines, words, bytes, then the name ([wc](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/wc.html)); `find` with no expression just prints paths ([find](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/find.html)); `touch` creates a missing file and otherwise only updates times ([touch](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/touch.html)); `cp` needs `-R` for directories and, by POSIX, overwrites an existing target silently ([cp](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/cp.html)). xv6's `grep` and `wc` read stdin only when given no file, which is dead code without pipes ([grep.c](https://github.com/mit-pdos/xv6-riscv/blob/riscv/user/grep.c), [wc.c](https://github.com/mit-pdos/xv6-riscv/blob/riscv/user/wc.c)).

| Command | Exact behaviour in Aeon (design inference) |
|---|---|
| `cp SRC DST` | Copy one file to a new RAM path; refuse an existing DST unless `-f`; refuse folders unless `-r`; the source may be a FAT disk file if the disk path syntax allows it, which turns the read-only disk into an importable library. |
| `mv SRC DST` | Rename or move a RAM file or folder within the RAM filesystem; same overwrite rule as `cp`. |
| `touch FILE...` | Create each missing file empty; do nothing to existing files (no clock, so no timestamp to set). |
| `head [-n N] FILE` | Print the first N lines (default 10). |
| `tail [-n N] FILE` | Print the last N lines (default 10); no `-f`, since nothing appends behind your back. |
| `wc [-l\|-w\|-c] FILE...` | Print `lines words bytes name` per file, or only the requested count. |
| `grep [-i -n -v -c] TEXT FILE...` | Print lines containing TEXT (plain substring, not regex); require at least one file; prefix the file name when given several. |
| `find [DIR] [-name GLOB]` | Recursively print every path under DIR (default current folder), optionally only names matching GLOB; its value over `tree` is searching by name. |

## Later, and left out: let missing OS features decide

**Add later**, once the first eight are stable. `hexdump FILE` (offset, 16 hex bytes, ASCII column) matters for an OS developer and complements `dread`; POSIX has `od` instead, so this is a convenience, not a standard ([od](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/od.html)). `sleep N` can run off the tick counter behind `uptime`; its use is mainly to stage demos of `job`, `race` and `wake`. `stat FILE` would print type and size only. `cmp A B` reports the first differing byte. A `more`-style pager helps once files exceed one screen. All of this is inference from Aeon's feature list.

**Deliberately left out**, by dependency (classification from the POSIX index, inferred, not tested):

| Needs | Commands | Why leave out |
|---|---|---|
| Pipes or redirection | `tee`, `xargs`, `cut`, `tr`, `uniq`, `rev`, `seq` | They only pay off when chained; `seq` is also not POSIX ([GNU seq](https://www.gnu.org/software/coreutils/manual/html_node/seq-invocation.html)). Revisit if pipes arrive. |
| Users or permissions | `whoami`, `id`, `who`, `su`, `passwd`, `chmod`, `chown`, `umask` | There is nobody to identify and nothing to protect. A fixed "root" answer would be a lie that invites false assumptions. |
| A clock | `date`, `cal`, `at`, `crontab`, timestamp-based `touch`/`ls -l` | `uptime` already gives the only time Aeon has. |
| The network | `hostname`, `ping`, `ssh`, `mail`, `ifconfig` | `uname` already prints the system name; the POSIX stand-in for `hostname` is `uname -n`. |
| Loadable programs | `which`, `type`, `env`, `nohup`, `time` on external commands, `make` | Every command is built in, so `help` replaces lookup. |
| Scripting | `test`, `true`, `false`, `expr`, `basename`, `dirname`, `ln` | Nothing consumes their exit status; hard links add filesystem complexity for no visible benefit. |
| Archives | `tar`, `gzip`, `unzip` | No archives to unpack and no way to run what comes out. |

A friendlier fix than adding stubs is for an unknown command such as `date` or `whoami` to answer with a one-line reason ("no clock on this system") and not a generic error.

## The prompt shows the full folder; `write` refuses silent replacement

**Prompt.** *Source-backed:* cmd and PowerShell show the full path ([prompt](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/prompt), [about_Prompts](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_prompts)); fish abbreviates parents to one letter ([prompt_pwd](https://fishshell.com/docs/current/cmds/prompt_pwd.html)); bash can keep only trailing components with an ellipsis ([PROMPT_DIRTRIM](https://man7.org/linux/man-pages/man1/bash.1.html)); Plan 9's rc shows no folder at all ([rc(1)](https://9p.io/magic/man2html/1/rc)). *Inference:* with no users there is no home folder, so skip `~`. Show the absolute path from the RAM root, as in `/docs/notes> `, with `/` for the root. Cap it near 24 characters by keeping the last two components behind `...`. This makes `cd`, `mkdir` and the new `mv` far easier to use blind, and costs one string build per prompt.

**Overwrite.** *Source-backed:* POSIX `>` truncates silently unless `noclobber` is set, then `>|` forces it ([POSIX shell language](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/V3_chap02.html)); PowerShell `Out-File` overwrites "without warning" unless `-NoClobber` ([Out-File](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/out-file)); Windows `copy` prompts interactively and `/y` silences it ([copy](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/copy)). No source shows what beginners prefer. *Inference:* Aeon's RAM files have no trash or undo, and `append` and `edit` already cover modify-in-place, so `write` is a deliberate "start fresh" command. I recommend **refuse by default**: `write: notes.txt exists (214 bytes); use write -f to replace`. Silent replace matches Bash and is a defensible second choice; a message printed after the fact protects nothing, and a y/n prompt adds modal state to a minimal shell. Apply the same rule to `cp` and `mv`, noting it knowingly departs from POSIX `cp`.

## Gaps and conclusion

**Open gaps.** Aeon's source, current `write`/`sort` behaviour and disk path syntax were not read, so "cp from disk" and any existing test scripts that rewrite files (which the refuse rule would break) are unchecked. The xv6 book, BusyBox and Toybox default configs, and GNU coreutils pages (HTTP 429) were not read. No hobby-OS source gave an ordered "first commands" list, and no beginner usability data on prompts or overwrite exists in the notes. POSIX edition is inferred from the URL path, and `mv`, `ls`, `sort`, `id` and `uname` spec pages were not fetched. The command tiers are my judgment from list overlap, not a measured ranking.

**Conclusion.** The useful finding is how small the gap is: Aeon already owns the highest-frequency commands and most of xv6's core, so eight additions complete a coherent file toolkit. The more valuable design work is the two policies, overwrite and prompt, because they shape every command added later. Decide the overwrite rule once, apply it to `write`, `cp` and `mv`, and revisit the "left out" table only when Aeon gains pipes, a clock or users, since each of those unlocks one specific row.
